# Заняття 9 · Демо та ноутбуки

Основні розділи ноутбуків працюють на синтетичних даних із відомим GT: датасети для них не потрібні.
Залежності — з кореневого `requirements.txt`. Файли `panels.py`, `mdmt.py` і `mtmc.py` мають лежати поруч із ноутбуками.

§7 ДЕМО 01 перевіряє висновки на реальних траєкторіях MDMT (два дрони, перехрестя):

```
python tools/fetch_mdmt.py --seqs 48                                  # ≈ 0.6 ГБ -> artifacts/mdmt/
pip install git+https://github.com/JonathonLuiten/TrackEval.git       # HOTA / DetA / AssA; без нього — спрощений evaluate
```

Без даних §7 пропускається, решта ноутбука працює як раніше. `mdmt.py` читає розмітку MDMT (CVAT XML) у форматі `make_gt`
і рахує метрики через TrackEval (`run_trackeval`); `python lessons/09-mot-reid/mdmt.py --seqs 48` готує GT для окремого запуску TrackEval.
Ліцензію MDMT автори не вказали: академічне використання з посиланням на Liu et al., IEEE TMM 2023.

## Очікувані числа (повні версії)

- ДЕМО 01, середнє по 8 сценах (SORT / BYTE / BYTE (центр)): MOTA 0.76 / 0.78 / 0.79, IDF1 0.61 / 0.56 / 0.66;
  через TrackEval — HOTA 0.56 / 0.53 / 0.60, DetA 0.69 / 0.70 / 0.71, AssA 0.46 / 0.40 / 0.50 («наївний» BYTE: DetA ↑, AssA ↓).
- ДЕМО 01 §7, MDMT 48, обидва дрони, TrackEval: при 30 FPS HOTA 0.71 / 0.72 / 0.72 (SORT / BYTE / BYTE (центр)), IDSW 19;
  при 10 FPS HOTA ≈ 0.60–0.61, DetA 0.69 → 0.57, AssA 0.72 → 0.65, IDSW 137. Варіант асоціації дає 1–2 п.п., частота кадрів — десятки.
- ДЕМО 02: при розсинхроні 300 мс ID persistence для авто ≈ 0; оцінка зсуву з треків — ≈ 320 мс; після компенсації — 1.0.

Після §6 ДЕМО 01 є експорт у формат MOTChallenge для TrackEval.
