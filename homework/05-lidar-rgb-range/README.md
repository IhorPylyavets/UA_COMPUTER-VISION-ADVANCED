# ДЗ 11 · LiDAR → RGB: перевірка дальності до об'єктів

До [заняття 11](../../lessons/11-rgb-lidar-radar-fusion/). ≈ 3–4 години, 20 балів.

Ноутбук: [`05_lidar_rgb_range_student.ipynb`](05_lidar_rgb_range_student.ipynb), ядро **Python (cv-advanced)**.
GPU не потрібен: повний прогін на 200 кадрах разом з абляцією — ≈ 20 с на CPU.

**Дані** (≈ 0,4 ГБ) — один раз, з кореня репозиторію:
```bash
python tools/fetch_kitti.py --object      # KITTI object: перші 200 кадрів training/ → artifacts/kitti/object/training/
```
[KITTI object](https://www.cvlibs.net/datasets/kitti/eval_object.php?obj_benchmark=3d), частина `training/`: `velodyne`,
`image_2`, `calib`, `label_2`. Ноутбук бере перші 200 кадрів за номером (`000000`–`000199`, ≈ 1000 об'єктів); інший шлях
до даних — через змінну `KITTI_OBJECT_ROOT`. Ліцензія KITTI: CC BY-NC-SA 3.0, для навчання підходить.

Якщо Google Drive не віддає архів (денний ліміт), ті самі кадри можна взяти з офіційних архівів (потрібна безкоштовна
реєстрація): `data_object_velodyne.zip` (29 ГБ), `data_object_image_2.zip` (12 ГБ), `data_object_calib.zip` (26 МБ),
`data_object_label_2.zip` (5 МБ). Розпаковувати повністю не треба:
```bash
for a in velodyne image_2 calib label_2; do
  unzip -n data_object_$a.zip "training/$a/0000??.*" "training/$a/0001??.*" -d artifacts/kitti/object
done
```

| Частина | Кроки | Слайди |
|---|---|---|
| 1 · калібрування і проєкція | `calib/*.txt` → `P2 · R0_rect · Tr_velo_to_cam` → `project()` з тестом на синтетиці | «SE(3) і конвенція імен T_to_from», «Осі LiDAR і камери», «Конвенція KITTI» |
| 2 · overlay | ≥ 5 кадрів, колір = глибина (log), колорбар | «Point-to-pixel: конвеєр і код», «LiDAR → RGB: колір = глибина» |
| 3 · GT дальності | 3D-бокс з `label_2` → медіанна глибина видимої поверхні (код готовий) | «Конвенція KITTI» |
| 4 · LiDAR і моно | frustum боксу → перший щільний кластер → медіана; `f · H / h` з апріорною висотою класу | «Дальність до цілі: LiDAR vs моно vs стерео» |
| 5 · метрики | таблиця по об'єктах, MAE / медіана / p90 і N по бінах 0–20 / 20–40 / 40+ м, відмови окремо | «ДЗ: LiDAR → RGB для верифікації відстані» |
| 6 · абляція | yaw ±0.5° / ±1°, розсинхрон Δt 10 / 50 / 100 мс | «Як довести, що калібрування правильне», «Бюджет похибки синхронізації» |
| 7 · звіт | точки на краях, LiDAR проти моно, абляція, три відмови | — |

У кожному з 6 TODO — від одного рядка (моно) до ≈ 10 рядків (кластер LiDAR); після кожного кроку `check()` показує ✅/❌.
Читання файлів, GT, малювання й цикли по кадрах готові. Читання KITTI object, розмітку, GT видимої поверхні і статуси
відмов ноутбук бере з [`kitti11.py`](../../lessons/11-rgb-lidar-radar-fusion/kitti11.py) заняття 11 — той самий код, що в
LIVE DEMO 3, тож ноутбук запускається з клону репозиторію.

**Чому GT — видима поверхня, а не `location`.** У `label_2` координата `location` — центр нижньої грані 3D-боксу,
а LiDAR бачить поверхню, повернуту до сенсора. Для машини, яка стоїть задом, різниця ≈ 2 м, і критерій 0.5 м стає
недосяжним. Тому ноутбук рахує `d_GT` як медіанну глибину 3D-боксу по пікселях його 2D-боксу, а різницю з «центром боксу»
показує окремим рядком.

**Критерії приймання** (слайд «ДЗ»):
- точки лягають на краї об'єктів на 3 кадрах з різною глибиною (overlay і кропи, відповідь 7.1);
- медіана `|d_lidar − d_GT|` ≤ 0.5 м до 40 м, або пояснення у 7.2;
- усі методи порівнюються на тих самих об'єктах, у кожному біні вказано N;
- відмови (оклюзія, обрізаний бокс, малий бокс, < 5 точок) — окремим рядком.
